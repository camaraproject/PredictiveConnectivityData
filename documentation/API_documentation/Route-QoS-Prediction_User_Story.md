# Route QoS Prediction API User Story

| **Item** | **Details** |
|---------|-------------|
| **_Summary_** | The API provides trajectory-aware, per-segment forecasts of network quality along a planned route, delivered by 4G/5G networks, before a device travels it. It is a scope enhancement of Predictive Connectivity Data: it reuses that API's prediction model but accepts a route (ordered waypoints) instead of an area, and returns a forecast per route segment instead of per grid cell. |
| **_Actors and Scope_** | **Scope:**<br>- Retrieve a per-segment QoS forecast for a planned route defined as an ordered list of waypoints.<br>- Optionally subscribe to forecast-change notifications for a previously-forecast route.<br><br>**Use Case 1: Connected Ambulance Routing**<br>- A dispatch application forecasts QoS along a candidate route before a time-critical journey, identifying segments where connectivity may be insufficient.<br>- Route selection and any resulting QoD invocation happen in the application, outside this API's scope; this API only produces the forecast.<br><br>**Use Case 2: Fleet Route Comparison**<br>- A fleet operator compares two or more candidate routes by their expected per-segment QoS before committing a vehicle to one.<br><br>**Use Case 3: Drone Corridor Validation**<br>- A drone operator validates that a planned flight corridor has sufficient coverage before authorizing the flight, extending Predictive Connectivity Data's existing area/volume forecasting to a linear corridor at per-segment resolution. |
| **_Pre-conditions_** | The client must provide the following inputs:<br>1. **Route:** an ordered list of 2 to 50 waypoints (Required)<br>2. **QoS Requirements:** one or more metric/target pairs (`LATENCY`, `THROUGHPUT`, or `RELIABILITY`) to assess along the route (Required)<br>3. **Device:** identifier for the end-user device (Optional; the MVP is device-independent, if a 3-legged access token is used, the device is derived from the token)<br>4. **Prediction Horizon:** upper time bound of interest (Optional)<br><br>To create a forecast-change subscription, the client additionally provides a `sink` callback address, the event types of interest, and optionally a subset of segment identifiers or a geographic area to scope notifications to. |
| **_Activities/Steps_** | - The client submits a route retrieval request including the inputs listed above.<br>- The API responds with a per-segment forecast, in travel order, each segment including:<br>&nbsp;&nbsp;&nbsp;&nbsp;- A mandatory `outcome.status` (`AVAILABLE`, `INSUFFICIENT_DATA`, `OUT_OF_COVERAGE`, `NOT_SUPPORTED`, or `UNAVAILABLE`)<br>&nbsp;&nbsp;&nbsp;&nbsp;- Best-effort `latencyMs` and `throughputMbps`, `null` when the outcome is not `AVAILABLE`<br>&nbsp;&nbsp;&nbsp;&nbsp;- A `reliabilityScore` per requested QoS requirement<br>&nbsp;&nbsp;&nbsp;&nbsp;- A `confidenceLevel` (numeric) and `confidenceBand` (`LOW`/`MEDIUM`/`HIGH`, cross-operator portable)<br>- Optionally, the client creates a forecast-change subscription; the API delivers CloudEvents notifications (`qos-degradation-forecast`, `qos-recovery-forecast`, `prediction-expired`) to the subscriber's sink as the forecast for subscribed segments changes. |
| **_Post-conditions_** | The requester obtains a per-segment QoS forecast that supports route-level planning decisions (for example, whether to pre-establish a QoD session on weak segments) ahead of departure, and may continue to receive forecast-change notifications for that route until the subscription is cancelled or expires. |
| **_Exceptions_** | Several exceptions might occur during the Route QoS Prediction API operations:<br>- **Invalid input:** Required fields missing or incorrectly formatted (e.g., fewer than 2 or more than 50 waypoints, missing QoS requirements).<br>- **Unsupported identifier:** A device identifier is provided that the operator cannot resolve, or is unnecessary given the access token already identifies the device.<br>- **Unavailable data:** A segment has insufficient or stale data, lies outside the operator's coverage, or a requested metric is not supported for it, reported via `outcome.status`, not a request-level error. |
